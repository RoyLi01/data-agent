## 2. AskData 的具体技术理解

### V1：重点是从问题到可信查询的分解

字段级索引包含关键词视图、语义向量视图和供重排使用的丰富文本。第三项不是又一种离线向量，而是在线重排的输入。先混合召回，再用原始问题重排，避免只围绕改写后的关键词优化而偏离用户要求。

规划把任务拆为数据库、处理对象、操作、输出目标；执行日志记录 Schema、计划、SQL、执行状态与结果，校验后按错误来源回退。我们保留结构化执行计划，不要求记录或展示模型隐式思维链。

### V2：重点是多轮交互与工具工程

- Coder 与 Data-Analysis 分工，区分新查询、已有数据分析与需要澄清的情况。
- Skills 先加载名称和描述，再加载正文、配置和必要资源；工具白名单与调用次数由程序约束。
- 数据库查询 Skill 已经要求 `query_contract`，包含粒度、源表、过滤、指标、输出列；本方案不能把“查询契约”说成原创。
- MCP 用于动态发现和调用数据源工具，凭据与权限留在服务端。协议本身并不自动提供数据权限保障。
- 路由阶段只需历史结果元数据，分析阶段按需加载数据；并非把每张结果表全部塞入对话。
- 按轮数聚合上下文和按 Token 限制短期记忆是两个不同机制。
- 澄清示例使用 LangGraph，但资料明确可采用自定义状态机。本方案用持久化状态与恢复接口实现。
- 部分记忆、安全章节仍为占位或规划，Harness 也是后续设想，不能一概写成资料已实现功能。

## 3. 评测给出的真正启发

AskData 报告的全量评测包含 430 个问题，覆盖增长、渠道和内容；资料给出 SQL 执行成功率约 99.30%，结果正确率约 82.56%，字段召回率约 95.26%，精确率约 19.44%。这些是原作者在其数据和判分设置下报告的结果，本次未复现，不能成为你的项目成绩。

它说明本项目最有价值的方向是解决“可以执行但业务含义错误”，而不是只做 SQL 语法重试。具体失败案例包括：

| 资料中的问题 | 根因 | 本方案的改进 |
|---|---|---|
| 使用不存在的日期字段 | 依赖猜测，未绑定真实 Schema | 字段绑定与版本检查，失败后重新检索 |
| 用激活记录数替代成功激活数 | 遗漏状态字段与业务谓词 | 指标注册时绑定成功条件，检索后补全依赖 |
| D7 留存的分子分母口径不一致 | 日汇总和注册明细粒度、队列不一致，关联可能放大 | cohort、窗口、去重实体与关联基数校验 |
| 查询信息流渠道 CPA 时遗漏渠道限制 | 过滤依赖未召回，SQL 仍然执行成功 | 检查合同中的必要谓词是否落实到 SQL |
| 内容分类走成创作者主分类 | 字段都存在但关联路径业务含义不符 | 为关系边标注业务语义，约束允许路径 |

原文已覆盖增长业务和粒度问题。本方案的特色是把这些经验变为可执行的约束、结果元数据和回归测试，不是改一个业务名称。

评测还需要注意：字段召回高不代表必要字段全部齐备；平均 SQL 耗时不等于用户端到端等待时间；展示的报告中澄清次数为零，不能据此证明澄清机制有效。必须另外构造歧义与多轮用例。

## 4. 哪些示例不直接搬到项目

1. Text2SQL 教学代码中的关键词检查不能替代 SQL AST 校验和数据库只读权限；`LIMIT` 也不能限制实际扫描开销。
2. SQLite `busy_timeout` 控制遇到锁竞争时的等待，不是通用 SQL 执行超时。[SQLite 官方说明](https://www.sqlite.org/c3ref/busy_timeout.html)
3. 代码解释器示例中的 `exec` 与字符串黑名单不能成为不可信代码的安全边界；拟议方案使用独立、受限执行环境。
4. AskData 不同演示片段与评测描述不是同一份可直接拼接的实现。例如关键词数组匹配并不等于 BM25；向量维度、索引参数必须与实际模型及索引匹配。
5. 工具调用优先采用模型原生结构化接口与参数校验，不照搬文本 `CALL` 的正则解析协议。
6. 课程销售场景的网页搜索有明确用途；增长指标分析不必为了凑工具数量加入互联网搜索。
7. 不复制原作者的召回率、准确率、业务收益、任职公司或上线规模。

## 5. 资料到方案的映射

| 资料基础 | 项目保留 | 针对本项目的深化 |
|---|---|---|
| Agent 工具决策与动态路由 | 工具调用循环、按任务暴露工具子集 | 强制执行口径和权限校验，模型不能跳过 |
| AskData 字段级混合检索 | BM25 + 向量 + RRF + 重排 | 按指标依赖补全状态、日期、去重键、关联键 |
| AskData 查询契约 | 结构化查询意图 | 从可信指标注册表建立约束，与 SQL 独立比较 |
| 双 Agent + Skills | 查询执行与分析报告分工 | 留存队列、渠道指标变动分解等专用技能 |
| MCP 执行工具 | 数据源与模型解耦 | 可信身份贯穿检索、执行及历史结果读取 |
| 记忆与结果复用 | 历史表引用、结构化会话 | 以粒度、字段覆盖、过滤、权限和新鲜度判断复用 |
| Reflection 与分层纠错 | 分类失败、有限重试 | 区分语法错误、语义错误、数据异常及基础设施错误 |
| 代码解释器 | 分析与可视化 | 固定统计函数优先，生成代码通过受限 Worker 执行 |

结论：拟议项目定位为“面向用户增长的可信数据分析 Agent”。简历主线是用数仓建模、指标口径与数据质量能力，让 Agent 生成的查询和分析更可靠。
