# Schema RAG、上下文和记忆实现

## 1. 知识库与字段三级索引

源数据是 `catalog.py` 中登记的表、字段、指标定义和允许关联；不是让模型猜 Join。分块以字段、表、指标、关系为单位，每块有稳定 ID，Schema 内容哈希用于版本校验。Schema 元数据不采用任意固定字数切块，避免将状态过滤、粒度和关联键切散。

同一字段生成三种表示：

| 视图 | 内容 | 使用位置 |
|---|---|---|
| `keyword_text` | 表名、字段名、别名、相关指标名 | BM25 关键词倒排评分 |
| `semantic_text` | 字段含义、所属表语义、适用指标 | 中文 Embedding 和向量召回 |
| `rerank_text` | 字段说明、表粒度、完整指标规则、允许关联 | CrossEncoder 联合编码问题与候选 |

这里的“三层”指参考方案中的字段三级表示，不是“库→表→字段”的逐层目录遍历。表级、指标级、关系级文档也参与召回；字段级知识保留父表上下文。

## 2. 混合召回与重排

```text
聚合后的请求（含当前明确条件）
 ├─ BM25(keyword_text) → Top 24
 └─ BGE(semantic_text) → 余弦相似度 Top 24
           ↓ RRF，k=60
        融合 Top 24
           ↓ CrossEncoder(query, rerank_text)
        重排 Top 8
           ↓ 指标注册表依赖补全 + Schema 图路径闭包
     字段、父表、Join 键、基数约束 → 查询计划上下文
```

两路召回独立计算。最终结果含各阶段候选 ID 和重排分数，便于检查错误发生在哪一段。真实本地模型已运行；fixture 使用词法哈希和词重叠，仅供快速回归。远程模型适配和 Milvus 可选路径仍需配置后联调。

Schema 图使用已登记关系做 BFS，补齐被召回表之间的中间表、关联键和 many-to-one 信息；提示多事实 Join 放大风险。图用于提供结构上下文，不等于血缘，也不能证明 SQL 的业务正确性。真正执行仍通过登记指标契约和只读 SQL 校验。小型目录使用内存向量和应用内图；这不是百万表规模性能证明。

## 3. 上下文聚合与动态路由

输入包括当前请求、最近 6 轮、异步摘要、候选结果的契约，以及用户选中的长期记忆。历史完整数据行不注入聚合提示词。

`live` 模式通过 `aggregate_request` Tool Calling 输出完整请求、引用结果、建议路由和强制刷新标记；返回结构由 Pydantic 校验，结果 ID 必须来自当前所有者可访问候选。然后检索 Schema，调用计划器生成登记指标契约，最终执行端确认路由。

`offline` 模式通过有限规则继承日期、指标、筛选和维度，并生成可查看的独立请求；不是通用自然语言理解。支持最近结果、首个结果、选中的收藏结果，以及显式刷新。当前显式修改覆盖继承条件。

| 情况 | 最终路由 |
|---|---|
| “新增”口径未明确 | 澄清，用户回答后恢复 |
| 契约相同且结果有效、完整 | 已有数据分析 |
| 完整渠道结果再筛选单一渠道 | 过滤后分析，记录父结果和变换 |
| 缺日期/设备维度、改变指标或日期 | 新数据查询 |
| 结果过期、Schema/快照/水位改变 | 新数据查询 |
| “刷新数据” | 强制新查询 |

模型建议不能跳过所有者、TTL、版本和完整性校验。页面展示聚合请求、建议/实际路由及原因。

## 4. 短期记忆

- SQLite 保存每轮问题、状态、已确认契约、澄清和结果引用，不复制结果行。
- 最近窗口固定 6 轮，每轮问题保留最多 1200 字符；是字符截断，不声称精确 Token 计量。
- 较早内容进入持久化摘要任务，单线程后台执行，不等待摘要完成才响应用户。
- live 使用模型摘要；offline 使用明确标识的结构化文本压缩。摘要最多 1600 字符，单个任务最多读取 24 条增量旧轮次。
- 新摘要按递增游标写入，过时任务不能覆盖更新摘要；失败记录保留，启动恢复 pending/running/failed 任务。
- 摘要用于语境；指标定义、结果契约和复用检查仍来自结构化存储。
- 旧版已完成任务在初始化时迁移到轮次存储。异步队列是本地单进程实现，不支持多 worker 争抢恢复；生产多副本需要租约和独立队列。

## 5. 长期记忆

用户主动保存 `field`、`table` 或 `result`，附加名称和说明。服务不自动把对话变成长期记忆。支持列表、文字搜索、勾选使用、删除；按 owner 隔离。删除的是记忆条目，原有会话和结果证据仍在各自存储中。

字段/表记忆作为检索提示，不授予工具或数据权限。结果记忆保存引用、契约和版本，不延长结果 TTL。跨会话首次使用必须显式选择；已经引用到当前会话的结果可继续追问。已过期收藏保留查询契约，但重新取数后才分析。旧 Schema 的记忆被标记并排除使用。

接口：

- `POST /api/memories`：`{kind,source_id,title?,note?}`；字段 source_id 为 `users.user_id`，表为 `users`，结果为 artifact ID。
- `GET /api/memories?q=...`、`DELETE /api/memories/{id}`。
- `POST /api/ask` 增加 `memory_ids`，最多 8 个，纳入幂等请求检查。
- `GET /api/sessions/{id}/context` 查看短期记忆和摘要状态。

## 6. 验证边界

自动化测试覆盖路由、引用切换、跨会话与连续复用、失效重查、owner 隔离、记忆删除、异步非阻塞、摘要重启恢复与游标防覆盖，以及模型接口的桩测试。真实本地模型检索单独评测，结果与规则解析测试分开。没有模型 API 凭据，尚未完成真实 LLM 聚合、计划、分析决策和摘要联调。
